# 无人机 + 视频结构化协同巡查平台（独立开发版）

这是根据用户提供截图和授权账号只读观察到的页面流程，重新编写的本地应用。**不包含参考站点的源码、数据库、真实人员资料、视频、品牌素材或三维模型，也不是原站的全功能等价交付。**

当前版本为 **0.1.0，可运行的本地管理与指挥界面首版**。区域总览采用全屏 Cesium 地图、左右半透明浮层、顶部五项指标、底部解析流和区域热度；指挥大屏保留蓝色深色布局，管理后台按最新要求重新设计为深色企业控制台。页面、字段和交互与参考站仍有差异，尚未逐页进行像素级验收。使用独立图标、合成演示数据和新设计的 SQLite 数据结构。

后台运营总览保留 224px 侧栏、58px 顶栏、桌面八列十一项指标（观察员按权限显示九项）、三列分组资源清单与最近操作。采用石墨蓝深色主题、半透明毛玻璃卡片和 SVG 菜单图标；桌面右侧最新预警与趋势图同排，小屏优先显示预警。增加按小时聚合的抓拍/预警趋势图、目标构成条形图、更新时间及快捷维护。资源页沿用真实 CRUD、筛选与分页接口；地图配置为本项目新增能力，不声称原站已有相同接口。

## UI/UX 优化

沿用原生 JavaScript ES Modules、Node HTTP API、SQLite、Cesium 和现有 CSS，没有引入新的 UI 框架。使用 `ui-ux-pro-max` 的本地设计与无障碍建议，保留桌面地图大屏和后台信息结构：

- 前台参照参考站的蓝色指挥风格独立重设计：深蓝渐变导航、青色标题标记、通透但清晰的蓝色面板、统一指标字形和层级；区域总览将标题和五项指标整合为一个顶部信息条。布控、无人机、执勤、查询、智能应用和档案库沿用统一前台样式。后台独立使用深色语义色、克制的毛玻璃和清晰的字体层级。表格采用紧凑行高、数字右对齐、隔行背景、悬停/键盘状态、右侧固定操作列；新增、编辑、详情、删除和系统配置弹窗保持既有业务规则。
- 主导航使用统一 SVG 图标；预警严重程度同时显示文字和颜色。区域总览在平板上采用地图、双列面板和底部数据区，在窄屏上顺序堆叠，避免地图图例与数据面板重叠。
- 提供键盘“跳到主要内容”、可见焦点、当前导航/切换状态、具名对话框和可聚焦的横向表格区域；原生校验汇总多个字段错误，保留已有描述关联，提交接口错误后聚焦提示。
- 尊重减少动态效果设置，保留现有导航、CRUD、查询、预警处置、权限、Cesium 生命周期及天地图配置。未接入的视频、飞控和算法仍明确显示未接入，不添加伪直播或伪在线数据。
- 区域总览默认仅显示点位，悬停可查看名称，也可通过地图工具显示全部名称；其他地图保持原有名称显示方式。地图工具改为统一 SVG，在小屏区域总览中排列为两列。保留天地图底图、注记、定位、缩放、图层和全屏功能，不改动已保存的地图参数。
- 区域总览左右面板采用约 75%–77% 不透明度的蓝色渐变底色，预警行使用轻量透明底色，使地图纹理可见；文字与图表不整体淡化，辅助文字针对明亮底图增强对比度。该透明度仅作用于两侧面板，不改变顶部指标、底部数据区或后台主题。
- 目标趋势图提供统一计数坐标、实线/虚线图例及“逐小时数据”对话框，展示本地数据库的 24 行抓拍总数和人脸记录数。未接入的数据总线展示等待状态，不再用抓拍趋势冒充总线吞吐量。
- 综合查询参照截图采用全屏地图背景、左侧条件、中间半透明可收起结果、右侧目标预览和检索概况。结果使用高密度卡片、24 条分页、时间/置信度排序、当前页导出和目标详情/定位；支持快捷时间、辖区、名称/点位/设备编号、性别、年龄段、颜色、置信度、当天与高置信度组合筛选。新增年龄段与设备编号仅保存维护数据，不推断缺失属性。
- 摄像头范围检索在 Cesium 地图连续点击多个地面点，双击或按 Enter / “完成选点”闭合多边形；Backspace / “撤销上一点”撤销顶点，Esc 取消。保留拖动矩形，也支持手动输入 WGS84 边界或 3–64 个 `[经度,纬度]` 多边形顶点（JSON）；拒绝自交与无效范围。绘制时暂停相机拖动，完成或取消后恢复。
- 综合查询地图展示摄像头位置，不受抓拍结果分页限制；范围内摄像头高亮，并显示选中数量及名单。服务端按摄像头位置选择范围内点位，再检索其关联抓拍，而不是按抓拍自身坐标筛选；离线摄像头仍可检索历史抓拍。范围条件可叠加其他属性与本地以图搜图。
- 抓拍维护界面新增“关联摄像头”下拉选项，保存 `cameraId` 并自动填写摄像头编号。明确的 `cameraId` 优先；只有未填写 ID 时，才能按全库唯一、完全一致的 `cameraCode` 匹配。重号、无关联或已删除摄像头的历史记录不进入范围结果，不按名称或邻近坐标猜测关联。已有演示抓拍未自动补关联，需要实际维护后才会在摄像头范围检索中出现；此功能检索本地已入库抓拍，不声称直接获取真实视频流。
- 以图搜图为本地视觉相似检索：浏览器使用 9 × 8 像素差分哈希与平均颜色距离比较授权图像，按可调阈值返回实际计算分数，不是语义模型、人脸身份识别或原平台算法。仅接受不超过 8 MB、2000 万像素的 PNG/JPEG/WebP。查询参考图片不上传服务器，离开页面释放；没有授权图片时明确提示，演示占位图不参与检索。远程图像需允许浏览器跨域读取（CORS），读取失败逐项显示且标记结果不完整；不使用服务器代理绕过授权。

看板默认展示带时间戳的本地快照，可手动“更新数据”或开启“30 秒自动更新”。自动更新在页面不可见、对话框打开、键盘操作看板或逐小时明细展开时暂缓；离开看板后清理计时器。刷新失败明确提示，保留上次快照，不伪造成功或新的曲线。趋势图有实线/虚线图例、坐标和可展开的 24 行数据表；目标构成同时显示名称、数量和占比。所有统计来自本地数据库，**不是设备遥测或实时识别结果**。

基础样式覆盖集中在 [ui.css](public/ui.css)，后台独立样式位于 [admin-theme.css](public/admin-theme.css)，前台独立样式位于 [screen-theme.css](public/screen-theme.css)，语义与校验增强位于 [ui.mjs](public/ui.mjs)。没有浏览器毛玻璃支持时使用实色卡片；减少动态效果时关闭模糊效果。本轮验证覆盖代表性组件和交互，不等于全站 WCAG 合规认证。

## M3E 影像采集、处理与多时相对比

入口为「无人机巡查 → 影像采集」。本轮采用用户确认的 **M3E 人工导入航线、飞后上传照片**流程；不向飞机或机场发送真实指令。

### 使用流程

1. 在地图连续选点，双击闭合范围，或填写 WGS84 JSON 顶点。支持 Enter 完成、Backspace 撤销、Esc 取消。规划当前只接受凸多边形；凹区域必须拆分，避免内部航点之间的直线转场飞出范围。单任务面积 100 m²–1 km²、20–120 m 相对起飞点航高、最多 500 个拍照航点，不跨日期变更线。
2. 设置航高、航速、重叠率、网格方向和计划时间，预览实际计算的面积、航程、照片数、GSD 和估时。计算采用 M3E 可见光相机 17.3 × 13 mm、12.29 mm 焦距、5280 像素宽度的理想平地模型；不能替代相机标定和地形跟随。
3. 保存任务后下载 `.kmz`，包内包含独立生成的 `wpmz/template.kml` 与 `wpmz/waylines.wpml`，使用 M3E 机型/载荷枚举、逐航点停留、云台角度和拍照动作。正射为往返网格；全景为一个位置的 25 个不同方向/俯仰拍照航点。M3E 存在天顶盲区，不声称拍完即得到无盲区 720° 全景。
4. **航线尚未经真实 M3E / DJI Pilot 2 验证。** 将 KMZ 传至遥控器，在 Pilot 2 中核验导入、相机、航高和动作，先进行合法安全的小范围实机测试。相对起飞点航高不是离地高度；当前没有避障计算、空域许可、天气检查、地形跟随、起飞/返航航段规划和电池分架次优化。地图金色线是地面路线示意，不是实测绝对高度轨迹。不得把页面估时作为电池或飞行安全保证。
5. 飞后选择任务，上传原始 JPEG，保留定位与 EXIF。一次按文件顺序上传，单文件 ≤100 MB，每任务 ≤5000 文件 / 10 GB，同时服务端最多 4 个上传；可查看已上传文件，失败后核对清单，不要重复上传已完成文件。上传时显示真实网络传输进度。平台校验 JPEG 文件头、尺寸和结束标记；影像解码和 EXIF/GPS 解算由 NodeODM 处理，不把合成坐标当作照片定位。
6. 明确填写**实际拍摄时间**后提交正射处理。后台实际调用 NodeODM 分阶段上传接口、提交任务、轮询任务状态、接收 GeoTIFF，再调用 GDAL 标准化、读取实际地理范围并生成 0–21 级 Web 墨卡托 XYZ PNG。只有输出文件确实存在后才登记可发布成果。亦可上传已有、正确地理参考的 GeoTIFF（当前上传限额同为 100 MB），只执行 GDAL 切片。
7. 已拼接 2:1 等距柱状 JPEG 可直接上传发布；此快捷入口的点位/方向使用任务规划值，相对航高不是实测海拔，须人工校准。需要精确位置与海拔时，使用「成果发布」登记正确元数据的已授权全景。**全景组图自动拼接尚未接通**，普通组图不会伪报成全景。
8. 「成果发布」可登记已授权外部 XYZ/TMS 瓦片或全景图，填写范围、真实拍摄时间、层级和方位。登记地址只保存索引，不代表外部服务连通；Cesium / WebGL 会实际加载并显式报告网络、CORS、纹理尺寸或图像比例错误。远程资源必须允许平台 Origin 跨域读取；不通过服务器代理绕过授权。
9. 「多期对比」选择两期正射，使用真实 Cesium 左右卷帘；也可按拍摄时间轴单期切换、播放/暂停。全景在地图显示热点，支持两期 WebGL 沉浸式查看，拖动、方向键和缩放联动，按各自 Heading 校准北向。请选择同点位、方向已校准的成果，不把不同位置的视角差异当作地表变化。页面隐藏时暂停时序推进，离开页面释放地图、图层、全景资源和计时器。

### U 盘与历史倾斜照片 → 快速 DOM

在「照片导入」填写批次名称和**真实拍摄参考时间**，一次选择 U 盘照片根目录，点击「按航次创建任务并上传全部照片」。按所选根目录的**一级航次子目录**自动创建独立任务，递归上传该航次下全部 `.jpg/.jpeg`；根目录直属照片另成一组，非 JPEG 文件明确统计但不上传。预览显示每个航次的张数和体积，**所有航次先预检，再创建任务**：每文件 ≤100 MB，每航次 ≤5000 张 / 10 GB，每批次最多 200 个航次；总目录可超过 10 GB，只要各航次分别合规。例如选择「奥体中心」可拆成 011、012、013、014 四个任务，不混合航次解算；五镜头目录应放在对应航次目录内部。直接选择一个航次的扁平照片目录仍只创建一个任务。

无需先画范围、生成航线或重新飞行，平台不修改原始文件。不同镜头目录中的同名文件按完整相对路径保存，引擎接收 UUID 文件名，避免相互覆盖。批次参考时间不是自动解析的各航次 EXIF 时间，提交处理前须分别核对真实拍摄时间及下视清单。中断后保留页面、目录和表单，再次提交会复用本批次任务，按原文件 SHA-256 验证已有照片后安全跳过；文件内容改变或旧文件缺少校验值会明确阻止复用。刷新、重新选目录或修改批次名/时间将开始新批次，不提供跨刷新自动续传；原任务及已上传文件保留，应先核对清单以免重复导入。已有任务中的「追加文件夹」仍是单任务上传，不自动拆分，超限时使用上述批次入口。

服务端在上传时读取 JPEG APP1 中标准 DJI XMP 的 `drone-dji:GimbalPitchDegree`（属性或元素），**仅 −90°±2°（含边界）的下视照片参与处理**；倾斜、缺失、无效或冲突的姿态均列出并排除。机身 `FlightPitchDegree`、文件名、文件夹名字不能替代云台俯仰角。非 DJI 相机或未保留该 XMP 的五镜头照片不会被猜测为下视；请先用厂家元数据确认并保留/修正可靠的云台姿态，不能简单更改标签伪造角度。旧上传文件未自动重新读取姿态。

部分 M3E 原始 JPEG 在有效图像的结束标记后仍有非图像尾部数据，尾部中可能再出现残留的 EOI。上传校验按 JPEG 段长度、熵编码和真实 EOI 标记逐块检查，不仅检查文件最后两个字节或搜索最后一个 EOI。记录 `jpegTrailingBytes`，超过 64 KB 时同时提供 `jpegWarning`，但不因已结束的有效图像附带较长尾部而误拒绝；整文件仍受 100 MB 和任务配额限制。保留完整原文件，不剥离 EXIF/XMP 或尾部。缺少真实 EOI、无效段长度以及元数据中伪装的 EOI 仍被拒绝；照片定位和图像解码是否合格由实际引擎进一步检查。

NodeODM 3.6.x 成果按其真实接口下载 `all.zip`，先拒绝 HTTP 200 中的错误 JSON 并校验 ZIP 文件头，再由 GDAL `/vsizip/` 读取固定成员 `odm_orthophoto/odm_orthophoto.tif` 进行标准化和切片，不把错误响应当作 GeoTIFF，也不批量解压任意归档路径。归档下载上限 4 GB，解码、地理参考及切片失败均保留失败状态，不发布假成果。

GDAL 3.13 的默认 `gdal2tiles` 新模式会跳过透明瓦片，微小覆盖范围的 0–3 级及边缘瓦片可能缺失，导致 Cesium 请求失败。适配器检测切片程序的 `--help`，存在 `--legacy` 时使用其完整金字塔模式，保存真实透明无数据瓦片；旧版没有该选项时保持原命令。发布前验证 0–21 每级均有 PNG，不以“生成了任意一张 PNG”冒充可加载的完整金字塔。后续 GDAL 若移除完整切片模式且输出不完整，将明确阻止发布，需要升级适配器。

任务显示下视／倾斜／未知数量，「查看上传文件」展示前 100 项及角度、筛选理由，「导出完整筛选清单」下载全部 JSON 记录。至少 3 张合格下视照片才能提交；数量达标**不等于 GPS、重叠率、模糊程度、曝光、架次一致性或测绘质量合格**。提交时锁定本次选中照片 ID 和数量；处理期间新增的文件不混入当前作业。成果保留 `nadir-dom` 处理模式及筛选计数，不能冒充全量倾斜三维重建。

当前按用户确认采用快速 DOM，不启用全量密集重建。倾斜照片有助于改善 DSM 和建筑投影，但开启 `orthophoto` 输出并不自动保证得到 TDOM，更不保证完全消除遮挡。TDOM 需要合适的多视角覆盖、相机标定、定位控制、DSM／Mesh 重建、可见性处理及成果质检；实际出图耗时和精度应以现场照片验收为准。

### 本机 GDAL 运行环境

本机已安装独立 GDAL 3.13.3 / Python 3.12.16，位于 `D:\GonganImageryRuntime\gdal`；项目 `data\imagery-engine\bin` 中的原生启动器为每个子进程单独配置 GDAL、PROJ 和 Python 环境，不修改全局 PATH。项目根 `.env` 保存这台机器的绝对启动器路径，启动 `node server.mjs` 时加载；配置样本保存在 `data\imagery-engine\native-imagery.env`。迁移到其他电脑时须重新安装并调整路径，不能只复制启动器。

### 本地持久化与处理状态

新任务、照片、成果和作业存入原 SQLite 的独立 `imagery_*` 表；文件存入数据库旁的 `imagery` 目录，走登录校验的私有读取接口。没有迁移、清空或替换原业务记录。原 SQLite 及其 `.settings-key` 必须配套备份，**同时备份影像文件目录**。当前不是 MinIO/S3，未实现 COG 在线读取、MBTiles、缓存集群或自动清理存储。

## 数据库与目录

```text
gongan
  server.mjs              启动入口
  server/app.mjs           HTTP API、鉴权、授权、校验
  server/database.mjs      建表、事务、合成数据初始化
  shared/catalog.mjs       资源字段、枚举、导航定义
  public                  独立前端源码、CSS、地图和图标
  scripts                 地图打包、构建、隔离浏览器测试
  tests                   API 与浏览器测试
  data/platform.sqlite    本地运行数据（首次启动自动创建）
  dist                    构建产物（不含数据库和凭据）
```

数据库不是原站模式。`records` 使用 JSON payload 和已索引的 resource/status/district 字段表达异构资源；`users`、`sessions`、`audit`、`settings`、`metadata` 分别保存账号、会话、审计、配置与初始化版本。`settings` 中的地图密钥为 AES-256-GCM 密文，其他地图参数为普通 JSON。普通资源间尚未建立业务外键约束。`sessions.user_id` 是真实数据库外键。

数据库路径可通过 `GONGAN_DATABASE` 覆盖。备份前请正常停止进程，再备份数据库文件及存在的同名 `-wal`、`-shm` 文件；不要把运行中的数据库单文件拷贝当作一致性备份。构建版默认使用 `dist\data`；若需与源码版共享同一库，先停掉源码版，再在构建版启动时设置相同绝对 `GONGAN_DATABASE` 路径。

**地图密钥的备份必须同时保留解密材料。** 默认首次保存密钥时在数据库旁生成 `platform.sqlite.settings-key`（32 字节）；数据库迁移/恢复时也需保留这个匹配文件。也可在首次保存前通过部署密钥管理系统设置 `GONGAN_SETTINGS_KEY`（64 位十六进制），此时不生成本地密钥文件。配置后不要直接更换或删除加密密钥，否则已有密文无法解密，服务明确报错而不会静默改用别的密钥。文件所在目录必须限制为服务账号可访问，尤其 Windows 上需配置 NTFS ACL；POSIX 创建模式为 0600，Windows 不保证该模式能设置 NTFS 权限。数据目录及 `.env` 不进入构建产物。未实现密钥自动轮换或外部 KMS 适配。

演示数据只在数据库首次初始化时写入，不会覆盖用户后续维护。删除演示记录不会在下一次启动时重新生成。

## 地图与第三方许可

地图使用 **Cesium + 天地图 WMTS Web Mercator (`w`)**，不再使用 Esri、OpenStreetMap 或示意地图。默认组合 `img_w` 影像和 `cia_w` 中文影像注记；矢量模式使用 `vec_w` 和 `cva_w`。支持 1–18 级缩放，保留“© 天地图 · 国家地理信息公共服务平台”署名。

推荐在后台配置你自己的天地图 **Web 服务**访问密钥：

1. 使用本地管理员登录，进入“地图配置”。
2. 选择与天地图控制台一致的“密钥类型 / 接入方式”。服务器端密钥使用后端代理；浏览器端密钥必须使用浏览器直连。将“密钥操作”切换到“设置 / 替换密钥”，填写本项目合法授权密钥。
3. 选择底图与地名注记，设置中心点、高度、朝向、俯仰角和瓦片范围，点击“保存地图配置”。
4. 右侧预览重新加载真实瓦片；其他已打开的大屏刷新后读取新配置。保存成功仅表示数据库保存成功，第三方授权、网络及影像响应仍需在预览中确认。

配置优先级：**后台保存的密钥优先于环境变量**；“保留当前密钥”不改变来源；“清除密钥”会禁用后台密钥及环境回退；只有显式选择“恢复使用环境变量”才重新启用启动时的 `TIANDITU_TOKEN`。页面从不回显原密钥；重新加载会清空未保存的密钥输入。恢复默认参数只恢复公开地图参数，密钥不变且仍需保存。

**浏览器模式的授权密钥不是对前端保密的服务器密钥。** 该模式通过已认证的 `/api/map/config` 返回 `browserToken`，供 Cesium 直接访问固定天地图 WMTS 地址；所有已登录的地图用户均可通过开发者工具查看它。后台表单仍不回显密钥，数据库仍加密保存。请在天地图控制台限制允许的域名/IP、权限和配额；不要将服务器端密钥切换为浏览器模式。服务器模式不返回 `browserToken`。恢复默认参数不会改变密钥类型/接入方式。

若服务器代理返回 `403 / 301012`，且提示“Key 权限类型为浏览器端”，应切换为浏览器直连或申请服务器端密钥，不通过伪造浏览器请求头绕过权限。代理兼容天地图影像的 `image/jpg` 响应，并规范化为 `image/jpeg`。

也可以通过部署环境提供备用密钥：

1. 将 `.env.example` 复制为同目录 `.env`。
2. 在 `.env` 中填写 `TIANDITU_TOKEN=你的合法授权密钥`。
3. 正常停止当前服务，重新 `npm start`，刷新浏览器。

也可通过启动进程的 `TIANDITU_TOKEN` 环境变量设置。构建版需要在 `dist` 同目录配置 `.env` 或使用环境变量。`.env` 已忽略，不会进入构建产物。**没有密钥时，Cesium 仍显示本地点位，但真实底图不可用，页面显示配置提示；不会回退到伪造地图或其他供应商。**

服务器模式下，浏览器访问认证后的同源 `/api/map/config` 和 `/api/map/tiles/{layer}/{z}/{x}/{y}`，密钥不回传；浏览器模式下，配置接口提供浏览器端密钥，瓦片由浏览器直接请求 `https://t0.tianditu.gov.cn/{layer}_w/wmts`。后台 `GET /api/admin/map` 仅返回公开参数和密钥配置状态；`PUT /api/admin/map` 需要管理员权限、来源/CSRF 校验以及 `If-Match` 配置版本。两种模式均不把密钥写入日志，数据库只保存密文。服务器代理限制图层名、级别、瓦片坐标、并发、超时及响应大小，拒绝错误/非图像响应；浏览器直连的配额和来源限制由天地图控制台管理。不要复用从参考站点提取的密钥。当前不支持其他供应商、自定义 WMTS 地址或天地图地形服务，不能将保存一个地址当作完整接入。
